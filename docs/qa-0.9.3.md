# Проверка Household 0.9.3

Проверка от 14 ноября 2026 года перед выпуском исправлений в 0.9.4: Claude Code 2.1.323, tmux, доставка сообщений, разрешения и жизненный цикл microVM. Ниже зафиксированы результаты локального QA; статус публикации и проверки GitHub Actions доступен у тега релиза.

## Найденные проблемы и исправления

| Приоритет | Проблема | Исправление и проверка |
| --- | --- | --- |
| P1 | Любой `PostToolUse` закрывал последний ожидающий запрос, включая чужое разрешение `Read` при завершении параллельного `Bash`. | Закрытие связано с вызовом, ходом и subagent. Если `PermissionRequest` не содержит id, используется однозначное соответствие `PreToolUse`. Неоднозначные одинаковые вызовы не угадываются. Проверены параллельные разрешения, ошибки инструментов и старый ход. |
| P1 | Подсказка в поле ввода считалась пользовательским текстом и блокировала доставку. | `promptSuggestionEnabled: false` передаётся на каждом запуске, включая старые homes. Захват сохраняет ANSI-атрибуты: серый/тусклый placeholder отличается от настоящего черновика с теми же словами, включая курсор внутри первого символа. |
| P1 | Выданный том не попадал в рабочие каталоги Claude. | В настройки текущей сессии попадают конкретные существующие каталоги `/volumes/<name>`, без `/volumes` целиком и без host paths. Реальный `Read` общей памяти проходит в manual и auto; соседний невыданный каталог требует разрешения. Read-only ограничение сохраняется на уровне mount. |
| P2 | Цитата `Do you trust the files in this folder` или `Bypass Permissions mode` в обычном сообщении блокировала доставку как стартовый диалог. | Готовность определяется структурой поля ввода. Настоящий экран доверия 2.1.323 сохранён как отрицательная фикстура; цитата проверяется как обычное сообщение. |
| P2 | Завершившийся запрос разрешения мог вернуть поздний `allow`, если обработчик проигнорировал отмену. | Ответ повторно проверяется после ожидания. Закрытие сессии, удаление бота и остановка mailbox отменяют ожидающие запросы. |
| P2 | Проверка терминала, начатая до открытия второго диалога, могла закрыть уже новый диалог. | Каждое открытие увеличивает поколение состояния, включая открытие при уже видимом диалоге. Добавлен регрессионный тест. |
| P2 | Доставка не проверяла copy mode и адресовала активную панель сессии. | Проверки copy mode до вставки и перед Enter; фиксированная панель `=main:0.0`. Реально проверены copy mode, смена панели и Escape из copy mode. |
| P2 | В базовых образах не было SSH-клиента. | `openssh-client` добавлен в Claude и Codex. Оба образа собраны, бинарники проверены. |
| P2 | После неудачного setup бот объявлялся запущенным без оговорки о готовности окружения. | При ошибке setup/on-start уведомление явно говорит, что окружение не готово, а агент запущен для ремонта. Сохранена политика: setup один раз на VM, повтор ошибки — только явно. |

Механизм восстановления setup после пересоздания VM сам по себе прошёл проверку: системная зависимость восстанавливается, даже когда постоянный HOME хранит `setup.status=complete`; обычный restart не повторяет установку. Для конкретного инцидента Jarvis нужны его сохранённый setup и журнал: по сообщению нельзя установить, устанавливался ли SSH через setup или вручную.

## Проверки

Базовая версия до исправлений: **1623 passed, 11 skipped, 0 failed**. Существовавший набор не покрывал описанную гонку.

- Финальный полный набор: **1637 passed, 13 skipped, 0 failed; 9210 assertions, 169 файлов**. Включает backend, web, доступ к секретам, сетевые правила, конфигурацию и жизненный цикл. Opt-in сценарии учитываются отдельно ниже.
- Настоящий Claude 2.1.323 и tmux: **1 passed, 40 assertions**, повторный прогон тоже прошёл. В контейнере с `--network none`, фиктивным ключом и локальным детерминированным HTTP-провайдером: старт, старый HOME, Unicode и многострочный текст, несколько сообщений в очереди, пользовательский черновик, copy mode, разрешение, вопрос с вариантами, план, диалог между paste и Enter, Escape, другая активная панель, большая вставка при 80×24, доступ к общей памяти в auto.
- Настоящий microsandbox 0.7.13: **9 passed, 108 assertions**. Telegram/MCP через тестовый Bot API; ключ подставляется только на host; обход proxy и доступ к постороннему порту заблокированы; daemon restart сохраняет VM; setup/on-start; CPU/RAM; read-only/read-write том; восстановление системной зависимости при пересоздании VM; backup/restore.
- `bun audit --json` в корне и `web`: оба результата `{}` — известных уязвимостей зависимостей не обнаружено на момент проверки.
- TypeScript и `git diff --check` проверены.

Native-тест добавлен в CI как отдельная задача `claude-terminal`. Release workflow зависит от этого CI, поэтому публикация ждёт терминальный тест.

## Воспроизведение

```sh
bun test
bun run typecheck

docker build -t household-qa-claude:0.9.3 src/agent-adapters/claude-code-tmux
E2E_CLAUDE_TMUX=1 bun test test/agent-adapters/claude-tmux-native.test.ts
E2E_MICROVM=1 HOUSEHOLD_QA_BASE_IMAGE=household-qa-claude:0.9.3 bun test test/microvm-e2e.test.ts

bun audit --json
(cd web && bun audit --json)
```

MicroVM-прогон требует microsandbox 0.7.13 и аппаратную виртуализацию. Имена VM, Docker-контейнеры, homes, порты и ключи тестовые. Тестовые runtime-ресурсы удаляются после выполнения; образы QA можно использовать для повторного прогона. Синтетические native-артефакты сохраняются в `/tmp/household-qa-native-artifacts`.

## Границы проверки

Проверено на macOS ARM64 с OrbStack и microsandbox. Linux/KVM и запуск нового CI на x64 этой локальной проверкой не подтверждены. Не использовались реальные аккаунты Claude или настоящий Telegram; поведение платного провайдера и успешные решения его auto-classifier не проверялись. Audit зависимостей не является доказательством отсутствия всех уязвимостей.

Claude может объединять несколько принятых через tmux сообщений в один следующий ход; `UserPromptSubmit` для queued-сообщений может ещё содержать id предыдущего хода. Проверяется принятие исходного текста, а не предполагаемое соответствие «одно сообщение — один Stop». Escape может вернуть прерванный запрос в черновик: Household сообщает `leftover` и не перезаписывает его.

Протокол и приоритет настроек сверены с [официальной документацией hooks](https://code.claude.com/docs/en/hooks) и [настроек Claude Code](https://code.claude.com/docs/en/settings). Поведение закреплённой версии дополнительно проверено исполняемым бинарником.
