Getting started

Household overview

A harness for harnesses. Household runs coding agents (e.g. the Claude Code CLI) as assistants you talk to in a messenger, each in its own VM, with network access and credentials under your control.

A daemon, house, runs on your Mac or Linux machine. It starts each pet in its own microVM, connects it to a messenger (e.g. Telegram) and stands between the pet and the internet. Each pet answers in its own thread and keeps its files and memory between conversations.

Core concepts

ConceptDescription
HouseA workspace for pets. Its pets share one allowlist, set of secrets, channel and owners.
ChannelA house's connection to a messenger, e.g. a Telegram bot.
PetAn agent running in a house: its own VM with a persistent home and memory, and its own chat thread.
AgentWhat a pet runs on: a coding agent harness, e.g. the Claude Code CLI or the Codex CLI.
SideworkerA temporary clone of a pet for a separate task in another directory. Same house, same permissions.
ScoutA one-task VM for access a pet doesn't have or for untrusted sites. Runs only with your approval and reports to you, never to the pet.

How it works

  1. Install the daemon

    house, on your Mac or Linux machine.

  2. Create a house

    Choose which hosts its pets may reach and which secrets they may use.

  3. Connect a messenger

    E.g. a Telegram bot.

  4. Add a pet

    Pick its agent, e.g. the Claude Code CLI, and set up its VM: a setup script installs the tools and packages it needs.

  5. Talk to it

    Write in its thread. It replies there, calling scouts or starting sideworkers when needed.

house onboard walks you through steps 2 to 4 in the terminal.

Network and secrets

All of a pet's traffic goes through the daemon:

  • Allowlist. Each house lists the hosts its pets may reach; everything else is blocked.
  • Placeholders. Pets see only placeholders for API keys and secrets. The daemon substitutes the real value at egress, in the HTTP header of a request to the secret's own hosts, so a leaked placeholder is useless.
  • Isolation. Every pet and scout runs in a separate VM. A sideworker sees its parent's home.
  • Scouts. No scout runs without your approval: you see the task and its capabilities, and you decide which secrets it gets. It starts in a fresh VM with none of the pet's files, which is deleted when you close it. It sends its result to you in its own thread; the pet gets its text and files only when you pass them on, so hostile content from untrusted sites stays out of the pet's context.

Substitution happens at egress, not inside the VM, so it works only for HTTP(S) clients that send the secret verbatim in a header. Database passwords, SSH keys, request signatures (e.g. AWS SigV4) and anything read from a file need the real value in the VM.
